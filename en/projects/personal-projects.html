Projets Personnels

On this page you'll find my personnal projects.

  • Breakdown Service

    Game in development solo on Godot. It's a job-sim close to Euro Truck Simulator.

    Breakdown service is a game that I started late 2025 and I'd like bring it to the finish line because I think it has potential. I'm still at the beggining of its development but a 20 pages GDD already exists. The game rules and its progression system are already defined. For obvious reasons, I don't want to say too much before it's ready. It's developed on Godot but I'm not closed to the idea of going to Unreal Engine if Godot's limitation brings too much difficulties.

  • Kitchen App

    Cooking recipe management app made on Godot. The development is almost done.

    The idea of this app came to me when I bought multiples cooking recipes and I had to take photos of the ingredients lists for shopping and keep the book open to cook. I'm aware that app like this already exist but I wanted to make my own to train at UI and external resources management, that we can save, delete and edit.

  • Task Force

    Task manager project made on Godot. Inspired by Range and Bongo Cat. The development is done.

    I came across a Range devlog by chance and liked the idea so I bought it. I have a small problem however with it: the app is always full screen. Earlier in the year I had Bongo Cat on my desktop. The idea therefore came to me to do like Range: a task time management app, but it's a small floating window that is always on top. I would have liked to gamify it a little bit and make the interface prettier but it's not in my plans.

  • Chrome Arena Redux

    Port of Chrome Arena Infinite, my last student project at Creajeux, from Unreal Engine 4 to Unreal Engine 5. The project is 90% done but on hold.

    To train myself on Unreal Engine 5, I decided to port my last student project from UE4, and to rework the whole project to optimize it and eventually make it available to be played for free.
    I reorganized all the files of the project which was a real chaos (it took me days) then redo all the materials to use less single instance. There are only a handful of materials in the project now, and the meshes use materials instances. All the blueprint code (almost the entire game) has been rewritten in C++. The AI logic is no longer in their AIController but instead I used BehaviorTree and EQS for a more efficient, maintenable and especially less buggy code!

    I documented the whole adventure on Youtube.

  • Godot Engine modification

    Addition of an editor setting from source code

    A frustration I often had with Godot is that the projects are by default in the "Documents" folder. As a result, they are mixed with the other documents. Strangely, I haven't found a way to define a default path for project creation (in reality there is one but you have to open a project → open the editor settings → find and modify the parameter which didn't seem logical).
    So I wanted to add this feature myself and possibly propose it as a contribution. When I made my proposal, someone had already made one 😓.

  • Texture resolution selector on Godot

    Surprisingly, Godot does not have texture resolution settings by default. Something that almost cost us in DeMETeRE. Not finding information anywhere to adjust the resolution of material textures at runtime, I created my own system.

  • Racing wheel input on Godot

    Godot doesn't detect by default racing wheels like the Logitech or Thrustmaster. Instead, each button is considered a gamepad button. I have listed the buttons and axes of my Logitech G923 steering wheel to be able to use it in game.
    The problem is that with another steering wheel, the keys could be different. What I would like to do is implement the steering wheel recognition directly into the engine with the SDL to facilitate the development of racing or aviation games on Godot.

  • GDInterface

    Plugin that allows to use interfaces with GDScript on Godot

    Sometime when trying to sleep, I think too much. Sometimes it give me ideas. From there the GDInterface idea came to me. While I call it 'interface', it's more traits that are used by the objects. GDInterface is in the middle checking and executing this trait without any typecheck.

    I've done Youtube tutorial that explains how it works. The Github repo is also well documented.


    Lien

  • Airlock system C++ plugin in Unreal Engine 5

    Unreal Engine plugin to create modular airlocked doors

    I generously contributed to the game Hiraeth, a space survival and exploration game on a barren planet. The developer asked me to create a modular system for airlocked doors. I decided to make it an open source plugin available on Github.

    A Youtube playlist exist to understant how to use it.

    A second demand was a turret that can detect the player and shoot at him. I made multiple sockets on the player character (head, shoulder, body, legs) and if the turret can see (with raycast) enough of them it detects the player and start shooting.

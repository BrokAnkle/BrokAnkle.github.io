Pattern

Programming patterns that I use:
  • Singleton

    A singleton is a unique, globaly accessible instance of a class. It's one of the easiests patterns to understand and use, but just as easy to abuse. I'm always looking to respect the SOLID principles including the "single-responsability", so my singletons stay clears and concises.

  • Observer

    The observer pattern is an event system where objects that doesn't know each other, don't references themselves, manage to communicate through events (Unity event, Unreal Engine delegate, Godot signals). Objects connect to events, and other objects emit messages to all these objects. This prevent dependancies between objects and spaghetti code.

  • State machine

    A state machine allows to decouple code that is run only in specific case in their own module. It's very common in character locomotion. Indeed, movement can exist in different states: idle, walk, run, jump, crouch... Locomotion code exist in each of these states and the character change its "current_state" according to the controller inputs (if I press on the jump input and that my "current_state" allows to jump, "current_state" become a JumpState).

  • Object pooling

    Object pooling is a pattern that allows memory optimization by keeping already instanciated object to re-use. This prevent allocation and de-allocation operation in memory that could cause stutters when lots of objects appear and disappear in quick succession.

  • Composition over inheritance

    With experience, I understand why we favorite composition over inheritance in object oriented programming. This makes a more concise, concentrated and modular code, unlike inheritance to excess where each derived class adds on top of what already exists. Inheritance stays very usefull, specially for creating a base class then a generation of derivated classes for example.

  • Interface

    Interfaces are used to create flexible and modular systems in object oriented programming (and so in game programming). An interface is an abstract class which group together a set of functions that each class implementing it must define. The most common examples are Interactable, Pickable, Damageable. These classes say "I can be interacted/picked up/damaged".

  • Data Driven Design

    DDD is a very important design pattern to get a clean and maintenable code in my opinion. It consist of splitting data from systems (code). For example, the player's statistics will be in their own file (JSON or another engine-specific format: Unreal Engine's Data Asset, Unity's Scriptable Object, Godot's Resource) and the code that handle this data is a the script attached to the object.

Specialties

  • 🎮 Gameplay

    Every game programmer starts with the gameplay, because without it, there is no game. It consists of the interaction between entities, the player's actions... in short, what the player can do and feel directly in the game.

  • 🤖 IA

    Non playable characters like friendly and ennemy bots. I like a lot the Behavior Tree system and GOAP (Goal Oriented Action Planing) to create smart bots in an intuitive manner.

    I can take advantage of this point to talk about generative AI like LLM. I use it very scarfully when writing code, the few times I've tried it, the generated code doesn't really match what I'm looking for, sometimes is full of errors. I use it to check when I have a doubt, or, when I attack a problem new for me, I can ask for an analysis and a starting point. There are some AI-generated codes that I used in my work, during my experience on the DeMETeRE project, I needed to control an object with high precision using a joystick. I therefore asked it for the best possible deadzone system for this problem and I adapted its pseudo-code to my project.

  • 🛠 Tools

    Programming tools is something I learned to appreciate the importance. When we work on a project that will take us years, and where we will repeat certain actions over several months, we are often prone to errors/omissions. I like to create tools to facilitate/automate the development of the project. Tools can also fill a missing feature of the engine.

  • ⚙️ Systems

    Making detailed and complex systems that will be used by gameplay programmers and desginers. It can be an inventory system with object weights, sorting, different sizes in the grid (or more recently, we see physics based inventory like in Sons of the Forest), etc... Or even, a dialog system with multiple choices that leads to different conclusions and events...

  • ✏️​ UI

    UI programming may seem daunting but for me it is important to create clean and satisfying interfaces, using tweens and shaders to bring each element to life. It is sometimes what makes the difference between an 'amateur' project/'prototype' to a 'refined' project.

  • 🥽 VR

    I discovered VR during my internship at Gambi-M. It's not as complicated as it seems. But VR development still has its quirks, obviously, the controls but also the optimization that must be anticipated as soon as possible.

  • 🧠​​ Design

    Although I am not a game designer, I pay deep attention to user experience and game feel, to what is fun in my game. I apply myself to document in a GDD and predicting how the different systems progress and interact with each other.

Organization

  • 📈​ Agile and SCRUM

    I use SCRUM for all my projects, even personnals. I use a scheduling software like Trello and give myself tasks to complete in a sprint (1 to 4 weeks).

    In my lead roles, I scheduled weekly SCRUM meetings where, with the small team, we reported on our progress, discussed our challenges, and estimated our own tasks for the following week.

  • 🗓️​ Trello/Hack'n'plan

    I think that a well-conducted project starts with an organization in the know. It is very important for me to note, describe, and estimate the tasks. At least for myself. During my lead roles, I took this part very seriously.

  • 📝​ Documentation

    It is important for me to document not only our code, but also the entire project development. My code is always commented where I consider it relevant. I note my task progress on my tool (Trello) and make and references UML diagrams that serve me for the design and code architecture.
